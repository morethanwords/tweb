# Ночная смена — общие правила

Пользователь попросил израсходовать остаток лимита аккаунта ночной смены (сейчас использовано {{UTIL}}, сброс
{{RESET_UTC}} = {{RESET_LOCAL}} по времени сервера) на полезную работу для tweb. Ты — одна из нескольких
параллельных сессий. До утра никто не отвечает: решай сам по этим правилам и по AGENTS.md / CLAUDE.local.md.

`N` ниже — `{{N}}`, папка этой смены. `{{RUN}}` — её имя: им начинаются имена всех твоих ворктри, веток и превью,
чтобы не столкнуться с ворктри прошлых смен, которые ещё ждут разбора.

## Рабочее место
- Работай только в своих ворктри основного репозитория, созданных от текущего master:
  `git worktree add -b {{RUN}}-<имя> {{REPO}}/.claude/worktrees/{{RUN}}-<имя> master` (зависимости и ловушки ворктри —
  в памяти, worktrees-toolchain-index). Одно независимое изменение — один ворктри, чтобы пользователь мог принять или
  выкинуть каждое отдельно.
- Файлы основной копии (`{{REPO}}`, кроме `N/`) и чужих ворктри не меняй — читать можно.
- Никаких коммитов, пушей, `git stash` без тега, записей через `gh` (комментарии, PR, issue), артефактов,
  scheduled tasks, новых сессий, сообщений кому-либо. Изменения остаются незакоммиченными в ворктри.
- Никогда не используй AskUserQuestion и plan mode: никто не ответит, сессия зависнет.
- Не трогай tmux-сессии и процессы, которые не запускал сам; превью останавливай только свои (`--stop`).

## Качество (как в AGENTS.md)
- Каждое законченное изменение: tsc, oxlint по тронутым файлам, один ближайший тест; видимое — живьём в превью
  (и в RTL, и с `?a11y=1`, если это интерфейс); ревью Codex через `scripts/codex-review.sh` по скиллу codex-review —
  до 3 полных раундов на изменение, подтверждённое чинить. Тяжёлые наборы — один раз в конце своего изменения и
  только те, что его видят; они ждут в общей очереди (`scripts/test-queue.sh`) — запускай в фоне.
- Изменение маленькое и локальное, без попутных рефакторингов. Видимое поведение не менять без нужды (память:
  keep-visible-behavior-when-fixing). Ожидаемые значения тестов — из правила, а не из кода.

## Превью
- `bash scripts/start-preview.sh --detach --id {{RUN}}-<твой id> --label '<1–2 слова>'` из своего ворктри,
  без sandbox. Одно превью на сессию за раз: переходя к другому ворктри, сначала `--stop --port <port>` старое.
- Сид превью живёт в `tmp/` своего ворктри, поэтому превью каждого нового ворктри — это новый вход в аккаунт превью
  (новая авторизация в его списке устройств). Поднимай превью только для того, что надо увидеть; логику проверяй
  тестами. Сколько превью ты поднял — пиши в отчёт.
- Аккаунт превью настоящий. Можно: читать, открывать экраны, отправлять в «Избранное» (Saved Messages) и удалять
  отправленное. Нельзя: писать в другие чаты, платить, менять настройки аккаунта, выходить из чатов, удалять чужое.
- Экраны приватности (Настройки → Конфиденциальность и их подэкраны) не открывай — ни руками, ни тестом, который
  обходит настройки: закрытие без изменений всё равно вызывает `setPrivacy` и стирает исключения «Premium-пользователи».
- Никогда не выводи `tmp/preview-dist/<id>/index.html`, `localStorage` и дампы хранилищ: там сид авторизации
  открытым текстом. Нужно проверить такой файл — `grep -c` по конкретному признаку, без вывода содержимого.

## Отчёт
- `N/reports/<твой id>.md`, по-русски, коротко. Обновляй после КАЖДОГО законченного пункта, не в конце:
  что сделано; где (путь ворктри); статус — «готово к ревью» / «нужно решение пользователя» / «не воспроизвелось» /
  «отложено»; как проверено (команды и результат); раунды Codex и что исправлено; разделы «Вопросы к пользователю»
  и «Для памяти» (в память сам не пиши — она общая с другими сессиями пользователя).
- Правило о приватных чатах из CLAUDE.local.md действует везде, включая отчёты.

## Ожидание и сторож
- Заканчивая ход, пока в фоне идёт долгая работа (тесты, Codex, сборка, workflow), сначала
  `touch N/state/<твой id>.waiting` — сторож не будит тебя 60 минут. Продолжив работу — удали файл.
- Сторож (bash-скрипт) пишет «Продолжай», если ты давно простаиваешь: продолжай свой поток, а если он закончен —
  бери задачу из `N/BACKLOG.md`. Сторож пишет только в сессию, которая стоит у приглашения ввода.
- BACKLOG: задачу берёшь через `mkdir N/claims/<slug>` (атомарно; не вышло — её уже взяли). Кончились задачи —
  придумай полезную в духе списка (баги, качество, скорость, тесты, паритет), допиши в BACKLOG.md, возьми и делай.
  Полезную для пользователей или разработчиков tweb, а не ради расхода.
- Перед каждым новым пунктом проверяй, нет ли файла `N/WRAPUP`. Есть (или пришло «Сворачивайся») — доведи текущий
  пункт до целостного состояния (или запиши, где остановился), обнови отчёт, останови свои превью, последней строкой
  отчёта напиши `СТОП` и больше ничего не начинай.
- Получив «Добор лимита»: одна небольшая задача, запись в раздел «После итога» под `СТОП`.

## Ресурсы
- Общая машина с другими сессиями пользователя. Не запускай `node build.js`; тяжёлые наборы — только через очередь;
  одно превью на сессию.
