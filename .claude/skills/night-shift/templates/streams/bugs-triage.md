# Разбор баг-бэклога (id: triage)

Баги — обычно приоритет ночи №1. Ты готовишь очередь для сессий-исправителей (fix1…), которые уже ждут её.

1. По скиллу `tweb-bugs` (`.claude/skills/tweb-bugs/SKILL.md`) собери открытые баги WebK: GitHub
   `morethanwords/tweb` (`gh`, только чтение, без sandbox) и bugs.telegram.org (WebK). Можно параллелить
   субагентами. Отсей уже исправленное в master (проверь по коду и `git log`), серверное, не воспроизводимое
   из описания, дубли.
2. Как можно раньше (первые 5 — в течение получаса) пиши очередь: файл на баг
   `N/bugs/queue/NNN-<slug>.md`, где NNN — приоритет (001 — важнейший): ссылки, суть, браузер/платформа,
   шаги воспроизведения, ожидаемое/фактическое, предполагаемые файлы кода, тяжесть, размер S/M/L.
   Исправители берут файлы по возрастанию номера. Очередь дописывай, пока есть годные баги (цель — 30–50).
3. Сводка — `N/bugs/TRIAGE.md`: таблица всего разобранного, включая отсеянное и почему.
4. Когда очередь готова, становись исправителем: дальше по `N/streams/bugs-fix.md` (твой id остаётся `triage`).
